#           go test -run '^$' -bench AppendSync -benchmem -benchtime=2000x -count 3 ./internal/journal

# Code:     the commit that adds this file
# Go:       go version go1.26.5 windows/amd64
# Machine:  i7-1165G7 laptop, Windows, internal NVMe SSD, default write caching;
#           File.Sync = FlushFileBuffers. Other apps running; no pinning.
#
# Reading the numbers:
# - EncodeFrame ~35-63 ns, 0 allocs: building a frame is negligible.
# - AppendSync ~1.4-1.5 ms: almost all of it is waiting for the device to
#   confirm the write (fsync).
# - SubmitDurable ~1.4-1.9 ms vs ~2.7 us for engine.Submit without a journal
#   (evidence/bench/2026-10-20-engine-overhead.txt): durability is ~500x the
#   rest of the work. One fsync per command caps this machine at roughly 700
#   durable commands per second for a single writer.
# - This motivates group commit (week 5): one fsync for a batch of commands.
# - Different disks, OSes and cache settings will give very different numbers;
#   a laptop SSD with write caching may also acknowledge before data is on
#   stable media. See ADR-0006 for what is and is not claimed.
#
